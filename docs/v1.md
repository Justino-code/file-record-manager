File Record Manager — v1

Overview

Version 1 is the initial functional version of the File Record Manager.

The project was created as a practical environment for studying C programming, particularly file handling and binary files. The initial domain chosen for the records is a book catalog.

The main goal of this version was to build a functional system while applying fundamental C concepts in a real project.

Objective

The objective of v1 was to create a simple record management system capable of storing and manipulating books in a binary file.

The version focuses on learning and applying:

- Structures ("struct")
- Functions
- Strings and arrays
- Basic pointers
- File handling
- Binary files
- "fread" and "fwrite"
- File positioning with "fseek"
- Searching records
- Updating records
- Logical deletion
- Basic input handling

Data Model

Books are represented using the following structures:

struct Autor {
    char nome[100];
};

struct Livro {
    int id;
    char titulo[100];
    struct Autor autor[3];
    int a_len;
    int ano;
};

Each book has:

- An identifier
- A title
- Up to three authors
- The number of authors stored
- The publication year

The records are stored in the binary file "livros.dat".

Operations

The system provides the following operations:

1. Add a book
2. List books
3. Search for a book
4. Update a book
5. Remove a book
6. Exit

File Storage

Records are stored directly as binary representations of the "Livro" structure.

The system uses standard C file operations such as:

- "fopen"
- "fread"
- "fwrite"
- "fseek"
- "ftell"
- "rewind"
- "fclose"

The fixed-size nature of the "Livro" structure makes it possible to locate records using their position in the file.

Record Identification

Each book receives an integer identifier.

When adding a new record, the program obtains the last record in the file and uses its identifier to generate the next one.

The initial identifier is "1".

Logical Deletion

Records are not physically removed from the file.

Instead, a removed record is overwritten with a structure whose "id" is "-1":

Livro l_removido = {-1};

The value "-1" acts as a sentinel indicating that the record is no longer active.

Listing and searching operations ignore records with this identifier.

This approach keeps the file structure simple and avoids physically reorganizing the file.

Update Strategy

Because records have a fixed size, an existing record can be updated by:

1. Reading the record into memory.
2. Modifying the structure.
3. Moving the file cursor back to the beginning of the record.
4. Writing the modified structure back to the same position.

For example:

fseek(fp, -sizeof(Livro), SEEK_CUR);
fwrite(&livro, sizeof(Livro), 1, fp);

Input Handling

The project uses helper functions for reading input:

- "readLine()" handles line-based input.
- "readInt()" handles integer input.

These functions provide a common mechanism for reading user input throughout the program.

Design Characteristics

The first version intentionally keeps the implementation simple.

The project uses:

- Fixed-size arrays
- Fixed-size strings
- Fixed-size records
- A single binary file
- Direct file operations

No dynamic memory management or complex data structures are required by this version.

Known Limitations

The initial version has several limitations that are intentional at this stage:

- The number of authors is limited to three.
- String fields have fixed sizes.
- Records have a fixed size.
- Deleted records remain physically present in the file.
- The file and record-management logic are closely coupled.
- Some functions depend on the current position of the file cursor.
- The system is specifically implemented around the "Livro" record.

These limitations provide opportunities for future versions to introduce new concepts and improve the architecture.

Version Status

Version 1 is the initial functional implementation of the project.

Future versions are expected to evolve the implementation as new C programming and software engineering concepts are studied.
